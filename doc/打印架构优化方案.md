# 打印机助手 · 打印架构优化方案

> 目标：Windows / macOS 双平台支持；拖入 txt / png / pdf / excel / word 等文件；点击一次打印；不打开任何第三方窗口；打印体验接近 WPS / Adobe。
> 技术栈：Tauri + Rust。

---

## 1. 核心结论

最可行的方案**不是**直接调用系统默认应用打开文件再打印，而是：

```
所有文件 → 统一转换为 PDF → 使用系统打印 API 发送打印任务
```

这是目前桌面打印软件最通用的架构。它带来三个关键收益：

1. **不打断用户**：不弹出 Preview / Word / Excel / Edge，全程在应用内完成。
2. **体验一致**：无论原始格式如何，最终都走同一条 PDF → 打印管线。
3. **可控性强**：页面缩放、纸张、份数、打印机选择都由我们统一控制。

> 当前代码已经接近正确方向（`lp file.pdf` 在 macOS 上是系统原生方案），
> 只需要把「调用应用打开并打印」改成「统一 PDF 管线」即可。

---

## 2. 推荐整体架构

```
            Tauri 前端（拖拽 / 文件列表 / 打印按钮）
                    |
                    |
              Rust Backend（编排 + 调度）
                    |
          ----------------------------
          |                          |
      文件解析层（转 PDF）          打印层（发任务）
          |                          |
          v                          v

  docx/xlsx/pptx                Windows Print API
        |                           |
        |                           |
        v                           v

   LibreOffice Headless         macOS CUPS (lp)
        |                           |
        |                           |
        v                           v

      PDF 统一格式  <───────────┘
        |
        v
    打印渲染引擎（MuPDF）
        |
        v
      打印机
```

分两层理解：

- **第一层 · 文件统一转换 PDF**：把任意输入格式归一化为 PDF。
- **第二层 · PDF 渲染打印**：把 PDF 交给系统打印 API。Windows / macOS 在此处分叉。

---

## 3. 第一层：文件统一转换 PDF

### 3.1 为什么必须统一

不要让每种格式各找各的打印程序：

| 错误做法 | 问题 |
| --- | --- |
| png → 图片查看器打印 | 弹出窗口、体验割裂 |
| pdf → Preview 打印 | 依赖 Preview、不可控 |
| docx → Word 打印 | 启动慢、占用授权 |
| xlsx → Excel 打印 | 同上，且排版易错位 |

正确做法：**所有文件 → PDF → 打印**，一条管线，统一体验。

### 3.2 文件支持方案

| 类型 | 转换方式 |
| --- | --- |
| PDF | 直接使用 |
| PNG / JPG / GIF / BMP / TIF / WebP | 自生成 PDF（按图片尺寸排版，保持比例） |
| TXT / RTF / CSV | 自生成 PDF（简单文本排版） |
| DOCX | LibreOffice headless 转换 |
| XLSX | LibreOffice headless 转换 |
| PPTX | LibreOffice headless 转换 |

> 图片与文本生成 PDF 成本低、可控，自己实现即可；
> Office 三件套**坚决不自己解析**，交给 LibreOffice。

---

## 4. 第二层：PDF 渲染打印（平台分叉）

### 4.1 macOS —— CUPS + `lp`

当前实现：

```bash
lp file.pdf
```

方向是对的，保留。流程：

```
PDF → CUPS → 打印机
```

优点：

- 系统原生，稳定；
- 支持所有已安装打印机；
- 不依赖任何 GUI 应用。

**删除**：`osascript` 调用 Preview 的方案，不要再用。

### 4.2 Windows —— Windows Print API

**不要**调用：

- `start file.pdf`（会打开默认程序）；
- Adobe Reader / Edge（第三方窗口）。

**应该**调用：Windows Print API。

```
Rust (windows-rs) → Win32 Printing API → Windows Spooler → 打印机
```

流程：

```
PDF → PDF 渲染(MuPDF) → EMF/XPS → Windows Spooler → 打印机
```

使用 `windows-rs` crate 调用 `Win32.Printing` 相关 API，直接把打印任务投递到系统打印后台，无弹窗。

---

## 5. 第三层：PDF 引擎选择

这一层决定打印体验上限（目标对标 WPS）。

### 推荐：MuPDF

官方：https://mupdf.com/

支持：PDF 解析、页面渲染、图片、打印、跨平台。

架构：

```
Rust → MuPDF → Windows/macOS 打印机
```

优势：Windows / macOS 行为一致，渲染质量高，体积可控。

### 不推荐

| 引擎 | 原因 |
| --- | --- |
| PDFium | Chrome 在用，但打印能力偏弱，主打浏览 |
| Poppler | Linux 很好，Windows / macOS 体验一般 |

---

## 6. 第四层：Office 文件（最麻烦的部分）

**不要自己解析 docx / xlsx**，成本巨大且易错。

推荐：**内置 LibreOffice（headless）**。

- 随包分发 `LibreOffice Portable`，或做「安装检测 + 引导安装」；
- 用户完全无感知：

```
xxx.docx → LibreOffice --headless → xxx.pdf → 打印
```

## 8. 完整打印流程

用户操作：

```
拖入：a.png  b.docx  c.xlsx  d.pdf
点击：开始打印
```

后台处理：

```
a.png   → 自生成 PDF
b.docx  → LibreOffice → PDF
c.xlsx  → LibreOffice → PDF
d.pdf   → 直接使用

合并：

a.pdf + b.pdf + c.pdf + d.pdf  →  merge.pdf

打印：

Windows: merge.pdf → MuPDF → Win32 Print Spooler
macOS:   merge.pdf → CUPS → 打印机
```

> 多文件合并为单个 `merge.pdf` 再打印，保证顺序一致、一次任务完成。

## 11. 实现进度（本仓库已落地）

已按上述架构完成第一轮重构，`src-tauri/src` 模块划分：

```
src-tauri/src/
├── lib.rs            # Tauri 命令 + 串联打印管线
├── pdf.rs            # 手写 PDF 生成（图片 DCTDecode 嵌入 / 文本 Helvetica）
├── converter/        # 第一层：文件 → PDF
│   ├── mod.rs        # to_pdf() 按扩展名分派
│   ├── image.rs      # macOS: sips→JPEG→嵌入PDF；其它: LibreOffice
│   ├── text.rs       # 纯文本 → PDF（含中文回退原生打印）
│   └── office.rs     # LibreOffice headless --convert-to pdf
└── printer/          # 第二层：PDF → 系统打印 API
    ├── mod.rs        # print_pdf() 按平台分派
    ├── macos.rs      # CUPS `lp`
    └── windows.rs    # MuPDF `mutool draw -o printer:`
```

`print_file` 流程：`converter::to_pdf() → printer::print_pdf()`，全程**不打开任何第三方窗口**（已删除原 Preview / Office 的 `osascript` 弹窗逻辑）。

### 已验证
- `cargo test`：文本 PDF、图片 JPEG(DCTDecode) PDF 的头部/尾部/xref 偏移结构全部通过。
- `tauri build`：macOS 发布版 `.app` 构建成功。
- 移除第三方应用弹窗：图片/Office 不再启动 Preview / Word / Excel。

### 已知限制 / 后续
- **macOS 图片**：用系统原生 `sips` 转 JPEG 后嵌入 PDF，零依赖、瞬时、无窗口。
- **文本含中文**：手写 PDF 仅支持 Latin-1，故中文文本走 CUPS `lp` 原生打印（同样是系统打印、无窗口）。
- **Office 文档**：依赖本机 LibreOffice（`libreoffice` / `soffice`）。未安装时打印返回错误、文件保留在失败列表可重试；后续可改为「随包分发 LibreOffice」。
- **Windows 打印**：按文档用 MuPDF `mutool`，需系统 PATH 提供 `mutool`（未在本 macOS 开发机编译/测试，已用 `#[cfg(windows)]` 隔离，不影响 macOS 构建）。
- **MuPDF 渲染引擎**：当前 macOS 走 CUPS `lp`、Windows 走 `mutool`；若要完全统一渲染，可后续把 `renderer/mupdf` 作为跨平台渲染层接入。
- **临时文件**：转换产物落在系统临时目录 `printer_assistant/`，后续可加打印后清理。
